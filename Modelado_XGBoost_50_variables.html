Modelo XGBoost para la predicción de transacciones

Equipo 4

En este notebook usamos XGBoost para estimar si un cliente realizará una transacción. Trabajamos con los datos de Santander y con las variables que se seleccionaron previamente durante la preparación.

El notebook permite trabajar con 200, 181, 100 o 50 variables. Ejecutamos una versión a la vez y mantenemos la misma configuración del modelo para comparar después los resultados con el equipo.

Para comenzar, subimos el ZIP de la versión que queremos probar a /content y seleccionamos su nombre en la celda de extracción. Esa celda guarda los archivos que contiene como train_final.csv y test_final.csv. No es necesario subir los CSV por separado.

El archivo de entrenamiento debe incluir ID_code, target y las variables predictoras. El archivo de prueba debe contener los mismos predictores y los identificadores, pero no target.

Para el experimento completo esperamos 200,000 registros en cada archivo. Si usamos menos registros, los resultados serán provisionales.

La selección de variables y las transformaciones previas deben realizarse sin utilizar información de validación o prueba. Este notebook no puede corregir una fuga de información que haya ocurrido durante la preparación.

  1. Selección y configuración del modelo

Elegimos XGBoost porque permite resolver problemas de clasificación con datos organizados en tablas. En este caso buscamos estimar la probabilidad de que target sea igual a 1.

Usamos 400 árboles, una profundidad máxima de 3 y una tasa de aprendizaje de 0.05. También aplicamos regularización y utilizamos una parte de las filas y columnas al construir los árboles para ayudar a controlar el sobreajuste.

Mantenemos estos parámetros en las distintas versiones del dataset. El notebook no busca automáticamente una configuración ganadora, ya que la comparación final se realizará con el equipo.

Como hay menos clientes de la clase 1, calculamos un peso para esa clase usando únicamente las etiquetas del conjunto con el que se entrena cada modelo.

Usamos un umbral de 0.5 para convertir las probabilidades en clases y calcular algunas métricas. ROC-AUC se calcula directamente con las probabilidades.

La separación conserva aproximadamente la proporción de ambas clases. Para comparar nuestros resultados con otros modelos, necesitamos usar los mismos registros en cada partición.

def ajustar_medianas(datos):
    medianas = datos.median()
    if medianas.isna().any():
        raise ValueError('Hay variables totalmente vacías en entrenamiento; revisa la preparación.')
    return medianas

def transformar(datos, medianas):
    return datos.loc[:, FEATURES].fillna(medianas).astype('float32')

def metricas(y_real, p):
    pred = (p >= UMBRAL).astype(int)
    return dict(roc_auc=float(roc_auc_score(y_real, p)),
        average_precision=float(average_precision_score(y_real, p)),
        accuracy=float(accuracy_score(y_real, pred)),
        precision=float(precision_score(y_real, pred, zero_division=0)),
        recall=float(recall_score(y_real, pred, zero_division=0)),
        f1=float(f1_score(y_real, pred, zero_division=0)),
        log_loss=float(log_loss(y_real, p, labels=[0,1])),
        brier=float(brier_score_loss(y_real, p)))

  1. Evaluación del modelo

La métrica principal es ROC-AUC. También calculamos precisión, recall, F1, accuracy y precisión promedio, entre otras medidas. Estas métricas permiten revisar aspectos que una sola medida no muestra, especialmente por el desbalance de clases.

Mostramos la matriz de confusión, la curva ROC y la curva de precisión y recall para facilitar la interpretación.

El archivo de prueba externo no contiene target, por lo que no podemos calcular estas métricas con él. Lo utilizamos para generar las predicciones finales.

La selección entre versiones y modelos se realizará con los resultados de validación y validación cruzada. La prueba final debe mantenerse fuera de esa decisión.

  1. Interpretación de los resultados

Revisamos las variables que más contribuyen a las divisiones de los árboles mediante su importancia por ganancia. Esta medida no indica por sí sola si una variable aumenta o disminuye la predicción.

También calculamos contribuciones SHAP para una muestra de prueba. Su signo muestra si cada contribución mueve la puntuación hacia la clase 1 o hacia la clase 0 respecto al valor base. Estos valores están expresados en log-odds y no representan directamente puntos porcentuales de probabilidad.

Como las variables están anonimizadas, no podemos asignarles un significado financiero específico ni interpretar sus asociaciones como causas.

Comparamos las curvas de entrenamiento y validación para revisar posibles señales de sobreajuste. Además, calculamos el lift del 10% de clientes con mayor puntuación para evaluar si el modelo ayuda a identificar un grupo con mayor concentración de transacciones.

El resumen generado por el código sirve como apoyo. Las conclusiones del informe deben basarse en los resultados obtenidos y en su revisión por el equipo.
